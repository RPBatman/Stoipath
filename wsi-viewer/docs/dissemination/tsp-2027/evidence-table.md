## Per-row validity rules (Part B, B4; protocol §4–§7)

- A cell (device × network × cache) with **N ≥ 10 valid runs** is a result; **3–9** is reported only with its N and the word
  "preliminary"; **< 3** is "insufficient runs" and is not quoted.
- Discard runs with an interrupted gesture, thermal warning, background reload, `contextLosses > 0`, or a cold run with
  `cacheHitFraction > 0`. Report N valid per cell; report p50 and p95 with bootstrap 95 % CIs (agents compute these Tue 3 Nov).
- The evidence pack states which device each number came from, that the REF CSS-transform page (if measured) was run on the same
  device in the same session, that input-to-photon is not claimed, and that OSD comparisons use the tuned profile.
- Headless (`!`) rows are never device numbers. SwiftShader frame times and dropped-frame percentages are not quoted at all.
- Bytes: cold runs give network bytes (`gestures[].bytes` → `mb_per_burst_p50`, `mb_total`; `cache_hit_p50` ≈ 0); warm runs give
  decode load. Tiles are the tissue-densest window (95 % tissue): byte figures are an upper bound.
