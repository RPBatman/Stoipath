1. What this concept does differently

The Workbench treats Stoipath Learn as one instance of the same shell the clinical and research builds use: a thin left rail that is both the panel switcher (Course · Slides · Layers · Step dock) and the tool rail (select/pan, point marker, measure, fit, bookmark), a left panel (course shell: progress, module list, step list; slide tray; layer list with ACL and provenance), the canvas with the shared HUD and navigator, a right dock (tour player, item card, expert’s view, review queue, gradebook, accessibility) and the status strip. Both panels are persistent, resizable (pointer drag or arrow keys on the role="separator"), pinnable and collapsible to the rail. The command palette (Ctrl/⌘K, also a visible button in the top bar and the “Commands” button in the touch bar) is the universal entry point: every command, step, slide, layer, item action, layout preset and setting is one search away with its shortcut shown, so the rail stays small and the learner, the author and the course director learn one grammar. The faculty Author studio and the director’s Cohort analytics are the “second page”: the same shell with the LTI roster role swapping the panel contents (demo strip → Page).

P2 · chrome costs no frames

Fixed grid tracks from --layout-*; panels resize only between gestures (the resizer is deferred while .is-gesturing); the only DOM over the canvas is HUD text, the navigator frame and the neutral context bar. In this mock the tissue is an SVG moved by transform only and the marks/hotspots/answer key/paths are drawn in a screen-space overlay exactly as the engine’s GPU overlay layers would be; in the product they are engine layers, not DOM.

P3, P9 · honest pixels and designed degraded states

Demo strip → Network: Cold 4G shows Soft — slow link with the ancestor rendered soft (never blank) and the slow-link chip; Offline pack shows the pack chip verbatim and the gradebook failure variant with the retry promise; Tile error keeps ancestors in the three failed tiles and shows “3 tiles could not be loaded — retrying”; Server slow and Classroom Wi-Fi use the §5.5 strings. Demo strip → Build switches the badge, label string and mode indicator and, in the Dx-capable builds, shows the §5.4 refusal (“this display cannot be attested”) until “Display attested” is ticked; Learn has no Dx mode, so the control is inert there.

P4, P7 · product and mode unmistakable; neutral chrome

LEARN badge and the full Learn string sit in the fixed top-bar slots; no accession, label image or patient field exists in the Learn build (the synthetic AP-26-04417 · DOE, JANE appears only when the demo switches to a clinical build). Everything within 32 px of the canvas is a neutral token; semantic colour appears only in dialogs and as the ≤ 0.016-chroma tints of the correct/incorrect alerts. Marks use the CVD-safe palette with the opposite-luminance halo (sienna for the learner’s Tumor mark, deep blue dashed for the answer-key ROI, chalk for measurement and paths).

P6, P10 · keyboard first; the chrome is the accessible layer

Every control shows its key; the Learn additions (N/⇧N steps, Space play/pause, ⇧↵ text alternative, ⇧R reveal) follow the principles §4.5 map; no Ctrl/Alt/F binding except CtrlK. The region-marking item has the candidates A–F dialog with Fly there and the structured text alternative; scoring is the same geometry service, never discounted for modality. Captions are on by default with a transcript; reduced motion makes flyTo instant and zeroes every chrome transition; focus is visible on the Commit button in the default state; targets are 24 px (44 px under a coarse pointer).

3. Key choices and trade-offs

  • Rail = panel switcher + tools. One 56 px strip (64 on pen/touch) carries the panel icons with counts and the four Learn tools. Saves a column against a separate activity bar; costs some discoverability for the tools, which the palette and ? repay.
  • Dock is a stack, not tabs. Tour player → item card → expert’s view → review queue → gradebook → accessibility, as collapsible <details>. The learner reads top-down in the order of the task; the footer carries the one primary action (Commit · Reveal · Next · Claim credit).
  • Context bar when the dock folds. On laptops the prompt survives as one neutral line in the banner slot. Trade-off: confidence rating and the expert’s view are one click further away there.
  • Sheet “peek”. On tablets and phones the item sheet opens at ≈ 230 px (stem · zoom gate · actions) and expands to 40 % (60 % on phones) on demand, so the canvas stays dominant while the prompt is always visible.
  • Role from the LTI roster, not separate apps. Learner, Author and Director share the shell; the IA’s Author studio and Director analytics screens become panel sets. Trade-off: the authoring page is denser than a dedicated studio would be.
  • Spaced-retrieval queue and confidence rating are shown (FR-E6, v1; v0.9) so the dock’s rhythm for later releases is settled now; they are tagged as later in the notes below.

4. What the judges should look at

  1. Press Ctrl/⌘K, type “fly”, “layer”, “reveal” or “light”: every panel action, step and setting is reachable and shows its key.
  2. Resize to 1440 × 900 and watch the panels become drawers and the context bar appear; open the dock with I or the rail button; pin/unpin the left panel with the pin button.
  3. Demo → Item: Mark placed → Committed → Revealed. The answer-key layer (deep blue, dashed) appears only at reveal; the expert’s path and the learner’s trace can be toggled in Layers; IoU and gradebook posting follow.
  4. Press ⇧↵ for the candidates A–F dialog; use Fly there, then commit from the keyboard; or “Answer in text instead”.
  5. Demo → Audience: the same shell carries the undergraduate lab (labels layer, image-region MCQ with Show region), the resident unknown (hidden diagnosis, timer, differential, trace vs attending) and the CME module (disclosure, attestation, certificate).
  6. Demo → Page: Author (record-a-tour, step and item editors with the publish lint and the deuteranopia check) and Director (cohort heat vs expert path, time-to-first-zoom, dwell share, item statistics, aggregate-only guard).
  7. Demo → Network and Build: every degraded state has a named visual and the §5 microcopy verbatim; the shell never shows a blank canvas.
  8. Tick “P1 guide” to see the central 50 % × 50 % exclusion zone; tick “Live markers” to see which elements the engine would drive.

6. Design notes (choices this concept makes; flag for the plan owner)

  • DB-1 · Region C does double duty. Principles §3.1 names the rail as the tool rail; here it also switches panels. Keeps the column count down; a reviewer may prefer the activity bar separated.
  • DB-2 · Pinned-by-default threshold at 2560 px. The design system’s breakpoints are 600/1080/1600/3200; this concept adds a 2560 pin default to satisfy P1 at 1920 × 1080. If the owner prefers the full Workbench look at 1920, P1 would need relaxing to ≈ 65 % for Learn only (not recommended).
  • DB-3 · Context bar in the banner slot. The banner slot was specified for banners; using it for the folded item prompt is new. It is neutral, 36 px, outside the central 50 %.
  • DB-4 · Author and Director as panel sets, not separate screens. The IA lists Author studio and Director analytics as screens; here they are roles over one shell. The IA inventory still holds; this is presentation.
  • DB-5 · Sheet “peek”. A ≈ 230 px sheet state below the ≤ 40 % maximum; it needs a drag/tap alternative pair (grabber + “Expand” button) which the mock provides.
  • DB-6 · The demo’s build switch shows the shared shell with the other three badges; the Learn build itself never carries Dx or PHI surfaces, and the clinical content shown is a one-line placeholder pointing to the clinical concept.
  • DB-7 · Later-release features shown now: spaced-retrieval queue and Anki export (FR-E6, v1), confidence rating (v0.9), CME claim (FR-E9, v1), exam timer (FR-E8, v1). Shown so the dock rhythm is settled; they would be hidden in v0.7.
  • DB-8 · CVD remap in the mock is a CSS colour matrix approximating the Dalton 2026 idea (Cr folded into Cb; coefficients R′ = Y, G′ = Y − 0.344·(Cb − Cr), B′ = Y + 1.772·(Cb − Cr)); the product applies the per-user LUT in the shader.

7. Known weaknesses (honest)

  • The canvas is a schematic SVG lymph node moved by CSS transform, not tiles: at 20–40× it reads as a diagram, not tissue; softness and tile errors are simulated with blur and clip paths.
  • The full “both panels pinned” Workbench look appears only ≥ 2560 px or when the user pins; at 1920 the concept at rest looks like a single-dock layout with a wider rail.
  • On laptops the dock is a drawer, so confidence, the expert’s view and the review queue are one click behind the context bar; the drawer covers the canvas edge (never the centre) while open.
  • The author and director pages are sketches: fewer states, no drag-to-reorder, no real recording; the publish lint is static.
  • The palette’s fuzzy match is a subsequence filter; the keyboard map lists the Learn map but not the presets’ remapped keys; dialogs trap focus minimally (Tab cycles inside, Esc returns).
  • Heatmaps and statistics are illustrative numbers; the deuteranopia and CVD matrices are approximations; H&E colours are the design system’s reference assumptions, not sampled scanner values.
  • Not screenshot-verified in the light theme in every state; no VoiceOver/TalkBack pass; the demo strip itself takes 44 px of every screenshot and is not product UI.
