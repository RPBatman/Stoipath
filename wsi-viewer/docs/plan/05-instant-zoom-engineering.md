## 1. The contract, stated operationally

"Instant and blur-free" is four invariants that `stoi-telemetry` checks on every presented frame, on every platform:

1. **Warm path adds nothing of ours.** When the tiles for the new view are resident in L0, input-to-photon (I2P) ≤ REF + 1 frame at p95, where REF is the platform floor measured on the same device with the reference CSS-transform page (web) or raw Metal/Vulkan quad (native), pointer and wheel reported separately. We cannot beat the compositor; we can refuse to add to it (verified on Chromium 153: the REF page and a WebGL-in-rAF viewer differed by 3 ms p50 in EventLatency traces).
2. **Never blank.** Blank-pixel frames = 0, always, including first open, context loss and offline. Guaranteed by the GPU-resident Pinned Base and the ancestor cascade.
3. **Bounded transient.** During a gesture the resolution deficit (octaves of magnification of what is drawn versus L\*) is ≤ 1 level on wired/LAN/Wi-Fi classes and ≤ 2 levels on radio, with NTF% ≤ 5/20/50 % by class (RA §4.4). Transients are bicubic on W+ and N, bilinear on W− and W60 (§11), never sharpened.
4. **Sharp at rest.** After the last input every visible pixel is sampled from L\* or from L\*'s parent at its fractional-blend weight within the TTS gate (warm-settle ≤50/100/250 ms p50 by class; cold fills under their own gate, §2); TTS is measured at **fade start**; the at-rest area-weighted deficit including the blend weight is ≤0.15 octave; NTF after TTS = 0 for unblended coarse pixels; pop-in count = 0 (any unfaded change of drawn level after the last input). Dx mode additionally raises the **Rendering Complete** flag only in this state, recomputed by the Class C verifier in `stoi-dx` (RA §3.2).

The operational definition of "same behaviour everywhere" (RA §1) is the **golden gesture replay**: a recorded input trace with its byte-arrival times *and its `set_budget` / upload-per-frame timeline*, replayed through `tick()`, must yield an identical request/cancel sequence and draw list **on policy-level fields** (TileKey, level, blend weight, request/cancel order, fade entries) on web, desktop, iPad and Android; `(array, layer)` slot ids are a per-platform snapshot, not a cross-platform assertion (adjusted after critique: the frame-time controller changes the upload budget per device, so slot-level identity holds only when uploads are not budget-limited). Everything below is designed so that replay is deterministic: no timers, no wall-clock reads inside the core, no platform-dependent branches in policy.

Doubling the refresh rate saves N × 8.33 ms for an N-vsync pipeline — 16.7–25 ms, two to three Deber JNDs — so the 120 Hz case for native shells rests on that, not on a single-JND coincidence. The cold path is won by *residency*: the prefetch lead is a distribution, not a point — at 3.33 levels/s and a log-uniform start scale a pinch crosses s = 1.0 ≈U(0, 300) ms after it starts (p25 75 / p50 155 / p75 225 ms; ≈85 ms median at a plausible phone pinch rate of 6 levels/s; pinch rate for pathologists unmeasured — gap-1 F7, Stage-1 gesture logging) (adjusted after verification: was "≈155 ms"), and 196 ms is the *minimum* inter-burst gap over 21,416 mouse-wheel events in a desktop DeepZoom viewer **[verified, Brunyé 2023]** — a floor used as a deadline, not a typical lead. Roughly a third of W-BB pinches therefore begin with a ≤1-level transient whatever the prefetch quality; hover/pointer-down prefetch (§6 item 4) is the mitigation and its hit rate is logged. On W-LAN and N-Desk the gap suffices at 1080p and the fill is upload-bound at 4K. Off-LAN the dominant term is bytes ÷ bandwidth plus slow start, which is why prefetch (§6), BDP pacing (§7), the L0-keyed DPR cap and the optional moving tier exist, and why no renderer change can help on W-4G: the radio promise is "never blank, ≤1 level soft during fast bursts, centre sharp ≈400–550 ms after the first input of a cold burst (≈300 ms after burst end when the fetch was issued at gesture start), full viewport ≈600 ms p50 at the DPR-2 cap, zoom-out and revisits instant from L0, overall TTS p95 ≈1.0–1.3 s because ≈15 % of settles are cold". ## 3. Frame loop and frame pacing

The core is a single-threaded state machine (RA §3): `tick(now_ns, inputs, viewport) → FrameOut { draw_list, requests, cancels, uploads, quality }`. Shells own the clock, the surface, the executor and input; they never make policy decisions.

```mermaid
sequenceDiagram
  participant In as Input handlers
  participant Shell as Shell (rAF / CAMetalDisplayLink / Choreographer)
  participant Core as stoi-core tick()
  participant R as Renderer
  participant W as Decode workers / rayon
  participant Net as fetch / HTTP client
  In->>Shell: push timestamped samples into ring (coalesced events; no other work)
  Shell->>Core: tick(t_present, samples, viewport)
  Core->>Core: camera substeps → L*, visible set → ancestor cascade → draw list → desired set → scheduler (BDP-paced)
  Core-->>Shell: FrameOut{draw_list, requests, cancels, uploads(≤ effective budget), quality}
  Shell->>Net: abort(cancels); fetch(requests, priority hint)
  Shell->>R: upload(uploads) centre-first, time-boxed, never into an array drawn in the last 2–3 frames
  Shell->>R: draw(draw_list): one instanced draw per texture-array pair
  Net-->>Core: on_bytes(id, bytes) → L2 write-through, dispatch to worker
  W-->>Core: on_decoded(id, tile) → L1; eligible for upload next tick
  Shell->>Shell: record quality (+ set_budget timeline); schedule next frame if dirty or gesture live
```

**Web shell.** Pointer, wheel and keyboard handlers do exactly one thing: append `(timestamp, kind, payload)` to a preallocated ring (consuming `getCoalescedEvents()`), then return. One `requestAnimationFrame` callback per frame calls `tick` with `t_present = rAF timestamp + one frame interval` (the frame being built is presented at the *next* vsync), drains `FrameOut`, and re-arms itself only while the view is dirty or a gesture/inertia is live. The loop never uses `setTimeout`; nothing on the hot path awaits a promise. Chromium delivers non-passive wheel events rAF-aligned (≈16 ms p50 `RendererCompositorToMain`), so wheel-driven zoom has input→tick ≈27 ms and warm I2P ≈60 ms p50 at the 2-vsync floor whatever we do (verified); wheel and pointer are therefore reported separately everywhere. On Chromium Android/Windows the canvas is created with `desynchronized: true` behind a feature flag, measured in Stage 0 (removes a compositor hop; never implemented on macOS, absent in Firefox/Safari **[verified]**). On Safari the loop runs at 60 Hz regardless (WebKit `PreferPageRenderingUpdatesNear60FPSEnabled` default true, verified in trunk source); Web Animations timelines can raise and GPU-canvas pacing can only lower WebKit's rendering-update rate, and neither lifts a per-frame redrawn WebGL/WebGPU canvas above 60 Hz (`framesPerSecondNearestFullSpeed`: 120→60, 90→90, 144→72 Hz); WKWebView is 60 Hz, 120 Hz only via Safari Feature Flags (bug 294338 NEW, second-hand). Correctness is unaffected, cadence is.

**Native shells** (gap-4 recipe, adopted in RA §2): iPad — `CAMetalDisplayLink` with `preferredFrameLatency = 1`, `maximumDrawableCount = 2`, `presentsWithTransaction = false`, `framebufferOnly = true`, overlays drawn in the same Metal frame, `CAFrameRateRange(80,120,120)` requested only while a gesture or inertia is live; `tick` runs in the display-link callback with `t_present = targetTimestamp`. Android — `SurfaceView`, `postVsyncCallback` rendering to the *preferred* frame timeline (never the earliest), two-image swapchain (`desired_maximum_frame_latency = 1`), `setFrameRate(120, ONLY_IF_SEAMLESS)` during gestures, `requestUnbufferedDispatch`. On both, system touch prediction (`predictedTouches`, `MotionEventPredictor`) feeds the camera *target only*, never tile requests. The iPad shell's touch *delivery* rate (60 vs 120 Hz UIKit delivery) is measured in G11 because it decides whether the native-over-web gain is ≈12 ms or ≈25–35 ms (adjusted after verification). Render quality is never adapted to the granted refresh rate (Apple's oscillation warning **[verified]**); a downclock is logged as a thermal event, not a dropped frame.

**Fixed-timestep camera.** `stoi-camera` integrates in substeps of 1/240 s from the last tick time to `t_present`, applying each input sample at its own timestamp. Pinch and drag set the camera *directly* (1:1, no smoothing); wheel, double-tap, keyboard and API set a *target* that the camera approaches with a critically damped first-order response (§10). Because the integration is deterministic in `(now_ns, inputs)`, replay is exact.

Zero-allocation rule: the core preallocates every per-frame structure (draw list, request lists, slot maps, rings); tile keys are packed `u64` `TileIndex` values; no hashing of strings on the hot path; the renderer reuses instance buffers (`write_buffer` into a persistent vertex buffer, never a new allocation per tile).

## 4. LOD selection, hysteresis and the fallback cascade

**Definitions.** k = device pixels per base-level pixel (the zoom); λ = log2 k. A level l (l = 0 base) has texel size 2^l base px, so its on-screen scale is s_l = k·2^l device px per texel. Following RA, **L\*+1 means the next finer level, L\*−1 the next coarser**. Resolution deficit of a pixel = (1 − f)·max(0, log2 s_child) + f·log2 s_parent octaves, i.e. **including the fractional-blend weight f** (adjusted after critique: a deficit that ignored the blended parent was blind to the softness trilinear introduces); NTF counts pixels sampled from a level coarser than L\* at weight 1 — a parent sampled at its fractional weight is not NTF, its softness is measured by the deficit.

**Target level.** L\* is the level with s ∈ [0.5, 1.0]: exactly one level satisfies this at any k, so no timers are needed. Boundary flapping from input jitter is removed by a guard band ε = 0.03 octave: switch finer only when s_L\* > 1.0·2^ε, coarser only when s_L\* < 0.5·2^−ε. DPR enters through k (device pixels). **The DPR cap is keyed to the L0 budget, not to the network class** (adjusted after critique: "capped at 2 on metered links" left the education pillar's main configuration — a 3 GB phone on classroom or hospital Wi-Fi — at DPR 3, ≈100–110 of 128 slots before a single revisit tile): the shell picks the largest DPR for which the un-evictable set (Pinned Base + the full ancestor chain of visible tiles) plus the working set (L\*, parent, ring, adjacent-level window) fits ≤ ~60 % of L0 slots at typical tile alignment and ≤ 85 % (the eviction ceiling) at worst-case alignment — **DPR 2 always on a 128 MiB L0**, DPR 3 only from 256 MiB (§9); the metered-link rule remains as a bandwidth saving on top. At rest, nothing is ever magnified: s ≤ 1.0 means every displayed pixel is backed by at least one texel.

**Sparse vendor pyramids** (added after critique). SVS/SCN step 4× between native levels, and index-in-place serving ("viewable seconds after upload") offers no level with s ∈ [0.5, 1.0] for half the zoom range until lazy synthesis has run for that region. Policy (RA §4.1): until the intermediate level exists, L\* draws the **finer native level minified up to 4×** with the fractional blend spanning two octaves — never the coarser level magnified >2×; the ≤4096-px levels are synthesised at index time; on the frozen-section path the ROI's intermediate level is synthesised synchronously (+25–120 ms server-side per tile); the "first view after ingest" row in §2 is gated separately from TTS.

**Fractional-LOD blend.** The pyramid is the mip chain. Each L\* tile is drawn blended with its parent at the same screen position with weight f = clamp(−log2 s_L\*, 0, 1): f = 0 at s = 1.0 (pure L\*), f = 1 at s = 0.5 (pure parent, which is then exactly at s = 1.0). This is trilinear filtering across pyramid levels: it removes minification shimmer and the 2× "pop" at level switches, and it is deterministic (no temporal state). It needs the parent resident, which the ancestor pin in §9 guarantees. Its at-rest softness (f = 0.74 at s = 0.6, parent magnified 1.67×) is bounded by the **at-rest area-weighted deficit gate ≤0.15 octave** (§15), measured on the Siemens-star goldens at s ∈ [0.5, 0.75] against pure-L\* bilinear and in a gap-1 F9 reader-study arm; blending only below s ≈ 0.75 (f = clamp((0.75 − s)/0.25, 0, 1)) is the recorded fallback if the study finds the softness perceptible.

**Ancestor cascade (per tile, per frame).** For each TileIndex at L\* intersecting the viewport:

```
fn draw_entry(t: TileIndex) -> DrawCmd:
    if L0.has(t):              return Blend(t, parent(t), f)            // normal case
    a = t
    loop:                                                            // climb; Pinned Base ends it
        a = parent(a)
        if L0.has(a):          break
    cmds = [Magnify(a clipped to footprint(t), kernel = class_kernel() if s_a > 1.0 else bilinear)]   // §11: bicubic W+/N, bilinear W−/W60
    for d in resident_descendants(t, depth ≤ 2):                      // zoom-out case: finer tiles already resident
        cmds.push(Overlay(d clipped to footprint(t)))
    quality.deficit[t] = log2(s_a); quality.ntf = true
    return cmds
```

The climb always terminates because the Pinned Base (levels with `max(w, h) ≤ 2048 px`: 11–22 tiles ≈ 11–22 MiB RGBA8, ≈23 MiB only for a square slide (adjusted after verification: was "all levels ≤2048 px per side, ≈21–23 MiB")) is GPU-resident for the slide's lifetime and the **full ancestor chain** of every visible tile — not only the parent — is un-evictable (§9). Worst case anywhere on a 100k² slide with nothing else resident is a 100k/2048 ≈ 49× magnification of the base, a known and bounded blur (≈5.6 octaves), never a hole; the Base Bundle (levels ≤4096 px, encoded, L1/L2) halves that wherever it has been decoded and the cascade draws it as soon as it is uploaded. On phones the Base Bundle is **decoded lazily by ROI**, not in one round (adjusted after critique: 64 tiles at 10–24 ms/tile across three workers is ≈210–510 ms on an A55, and on 4G the ≤8–10 MB worst-case bundle transfer is seconds, so "halves the blur within one decode round (≈60–200 ms)" was wrong on the floor classes; on W-LAN/N-Desk it is ≈60–150 ms).

**Settle contract, TTS and Rendering Complete.** When the input ring has been empty for ≥1 frame, the scheduler promotes every missing L\* tile to tier 0 and the frame is marked `settling`. Late tiles keep the ancestor on screen; the engine never substitutes a lower-quality render of the *target* to end the animation. **TTS = last input → the first frame in which every visible pixel is sampled from L\* or from its parent at the fractional-blend weight, i.e. at fade start** (adjusted after critique: "no cross-fade in progress" made the ≤50 ms W-LAN gate unreachable whenever any tile landed after the last input); the fade's duration is excluded from TTS and counted in BAT, and pop-in count stays a separate metric. When additionally no magnification kernel is active, no fade is in progress and (in Dx mode) no derived-tier tile (`enc=m` or 8-bit preview) is on screen, `quality.rendering_complete = true`, recomputed independently by the `stoi-dx` verifier.

**Cross-fade — one landing rule.** Any change of drawn level at a pixel after the last input is faded: ≤3 frames (50 ms) on a settled frame, ≤100 ms (6 frames at 60 Hz) during gestures (adjusted after critique: the earlier "a tile landing into a fractional-blend slot needs no fade" could not occur, because while the child was missing the parent was drawn at weight 1, not at weight f, so its weight dropped abruptly — a pop by this section's own definition). MapLibre's 300 ms is too slow for diagnostic work (note 04 F7).

## 6. Predictive prefetch

Prefetch is paced below any visible need (≤1 BDP of prefetch bytes in flight, §7), tiered, and *logged* (predicted vs actual at burst end, prefetch waste, hover hit rate) from M0, because the only field measurement of naive prefetch is 74.1 % waste **[verified, Kayser/Wienert 2009]** and the Stage-1 acceptance is ≤50 % (RA §4.2 correction 4); moving-tier bytes count inside waste and bytes-per-gesture.

```
// runs inside tick(); all quantities in device px, levels, seconds; One-Euro (Casiez 2012) filters
state: pos_f = OneEuro(min_cutoff 1 Hz, β 0.007)   // pointer / centroid position → velocity v
       lam_f = OneEuro(min_cutoff 1 Hz, β 0.05)    // λ target → zoom rate r (levels/s)
       burst = { active, sign, samples_agree, λ_start, t_start }

fn predict(now, cam, focus) -> Vec<Want>:        // Want = (TileIndex, tier, score)
    wants = []
    // 1. Pan cone — tier 1, direction-weighted ring
    v = pos_f.velocity(); if |v| > 40 px/s:
        for τ in [0.10, 0.25, 0.50] s:
            shift = clamp(v·τ, ≤ 1 viewport)           // user pan-speed ceiling (Molin 2015)
            wants += tiles(L*, viewport shifted by shift) \ visible, tier 1, score ∝ τ
    // 2. Ring — tier 1
    depth = metered ? 1 : 2
    wants += ring(L*, viewport, depth) \ visible, tier 1, score by distance
    // 3. Zoom intent — tier 1, ±300·DPR px window around focus (gaze–cursor median 293 px, Raghunath 2012)
    r = lam_f.rate()
    if |r| > 0.5 levels/s:
        if !burst.active: burst = start(now, sign(r))
        burst.samples_agree += (sign(r) == burst.sign) ? 1 : -2
        win = window(focus, ±300·DPR)
        wants += tiles(L* + burst.sign, win), tier 1, score by distance to focus   // centre-first: only ≈2–5 tiles land inside the lead on W-4G
        // destination predictor (RA §4.2 correction 4): ≥2 consistent samples and confidence
        A_hat = clamp(|r| · T_hat, 1, 6)                        // T_hat = 0.8 s prior; replaced by the online
        conf  = sigmoid(burst.samples_agree − 2) · sat(|r| / 2)  //   burst-duration estimate after Stage 1 logging
        if conf ≥ 0.7 and A_hat ≥ 2:
            L_dest = L* + burst.sign · round(A_hat)
            wants += tiles(L_dest, win scaled to L_dest), tier 1, score 1     // skip intermediates
            log(predicted = L_dest)                                           // waste accounting at burst end
    else if burst.active and now − last_input > 0.15 s:
        log(actual = L*, lead_observed); burst = end()
    // 4. Hover / pointer-down — tier 1 (the mitigation for the ≈⅓ of pinches whose lead is < first byte + window transfer)
    if pointer_down_or_hover and !burst.active: wants += tiles(L*+1, window(focus, ±300·DPR)), tier 1; log(hover_prefetch_issued)
    // 5. Idle fan-out — tier 2, unmetered only
    if queue.empty() and !metered and v == 0 and r == 0:
        wants += tiles(L*+1, viewport), tier 2; wants += ring(L*−1, viewport, 1), tier 2
    return wants

pacing(): BDP = bw_ewma · rtt_p50 (≈140 KB W-4G, ≈310 KB W-BB, ≈125 KB W-LAN)
          total in flight ≤ 2·BDP; prefetch in flight ≤ 1·BDP; tier-0 always admitted
          a tier-0 arrival pre-empts the lowest-score prefetch (cancel if < 30 % bytes received)
          // adjusted after critique: the former "≤50 % of bw_ewma × 0.5 s, ≤25 % of slots" put ≈250 ms of our own bytes
          // ahead of a tier-0 request on W-4G and W-BB and could not carry the 40–50 tier-1 wants per frame
```

Design points: the adjacent-level window is fetched from the *first* sample, centre-first, because it is right 100 % of the time the gesture continues; its size per class is **derived from the byte budget and the BER gate, not a fixed fraction** — on W-4G, lead × bandwidth is ≈0.23 MB at the p25 lead (75 ms) to ≈0.5 MB at p50 ≈ 2–5 settled tiles, which is what the W-4G BER floor of ≥70 % (02 NFR-P8) buys; on W-BB ≈0.9–1.9 MB ≈ the whole 9–16-tile window at p50. Stage-1 prefetch is sized to the **p25 lead (≈75 ms)**, not the p50 (adjusted after verification). The destination skip is gated because 34 % of pathologist bursts span < 2.3 levels **[verified, Brunyé 2023]** and a wrong skip leaves nothing resident; "66.4 % ≥5×" counts magnification-change events, not pinch-level skips. Pan paths are near-linear (3-point linearity 0.85 **[verified, Kayser 2009]**), so the cone is extended along the dominant direction and never beyond one viewport. All constants (τ set, β, thresholds, T_hat, window radius) are a versioned `PrefetchPolicy` struct in the core so that the Stage-1 reader study and telemetry (D9: pinch levels/s, burst gaps, lead distribution) can recalibrate them without touching code paths, and the golden replay pins them per release.

```
fn schedule(wants, now):

    for r in inflight: if !wants.contains(r) and r.tier > 0 and r.bytes < 0.3·r.expected: cancel(r)
    queue = dedup(wants \ resident \ inflight) sorted by key
    coalesce_centre(queue)                                    // ≤9 tier-0 tiles → 1 bundle (edge: one range per shard)

        r = queue.pop_min()
        if r.tier == 0:                                       // always admitted

            emit Request{ id, url(r), priority 'high', abort_token }
        else if inflight_bytes + r.expected ≤ 2·bdp and prefetch_bytes + r.expected ≤ bdp and inflight.len < cap_secondary(class):
            emit Request{ id, url(r), priority 'low', abort_token }
        else: continue_to_next_tier0_or_break
```

Fencing: a slot is written only when its last GPU read has retired. ## 10. Zoom and pan mathematics

Camera state: `c` = slide coordinate (µm, via the Manifest's µm/px) under the viewport centre `v`, `λ = log2 k`. Screen point of slide point w: `p = (w − c)·k + v`.

- **Pointer-anchored zoom** by factor f about screen point p: `k' = k·f`, `c' = c + (p − v)·(1/k − 1/k')` (the slide point under p stays under p). Applied per substep, so a moving anchor (two-finger pinch that also translates) is exact.
- **Pan** by screen Δ: `c' = c − Δ/k`.
- **Pinch**: `λ_target = λ_0 + log2(d/d_0)` from finger distance, anchored at the centroid, 1:1 with no smoothing, last coalesced sample ≤ t_present wins; `touch-action: none`; `pointercancel` ends the gesture and keeps the camera. Safari 18.2 coalesced events lack `pointerId` (Flutter workaround applied) **[verified]**. Pinch kinematics of pathologists are **[unverified]** (Brunyé 2023 is mouse-wheel data); Stage-1 gesture logging (D9) replaces the 3.33 levels/s assumption.
- **Wheel**: read `deltaMode` *before* `deltaY` (Firefox switches to lines once read **[verified]**); normalise lines ×40, pages ×300, pixels ×1 (OpenLayers constants); accumulate; **300 device-independent px = 1 level** (a 100 px Chrome notch ≈ 0.33 level ≈ 1.26×, close to OSD's 1.2× `zoomPerScroll` (verified) but continuous); clamp ≤1 level per event; `ctrlKey` wheel = trackpad pinch with ×3 multiplier and the |delta| < 4 trackpad heuristic (OL); legacy Safari `GestureEvent` only as a fallback. Easing toward the accumulated target is critically damped in log space with τ = 100 ms (`λ += (λ_target − λ)(1 − e^{−dt/τ})`), anchored at the pointer each substep — never quantised ±1 per event, never a 1.2 s spring. Wheel events arrive rAF-aligned in Chromium (§3), which the camera integrates by timestamp, so cadence does not change the path.
- **Inertia** (mouse/touch release): velocity from the One-Euro filter; `v ← v·e^{−dt/τ_i}` with τ_i = 200 ms, stop below 20 px/s, total travel capped at one viewport (the pan-speed ceiling pathologists exhibit **[verified, Molin 2015]**); trackpad two-finger pan gets no inertia (OS already supplies it).
- **Double-tap / click**: 2× (one level) in log space over 220 ms, anchored at the tap; keyboard ± one third of a level per press, arrows one quarter viewport, both animated 150–300 ms.
- **Pen**: `pointerType == 'pen'` routes to the annotation tool by default while a finger pans (tool routing by pointer type); barrel button = pan; coalesced events for ink; predicted events to the camera target only; `UIHoverGestureRecognizer`/`zOffset` hover loupe on M2+ iPad.
- **Page zoom guard**: `VisualViewport.scale ≠ 1` is detected and the slide, not the page, receives the pinch.

## 11. Filtering, sharpening and the shader set

One WGSL set, translated to GLSL ES 3.00 by `naga-cli` at build time for `stoi-render-gl` and run natively through wgpu; goldens ≤1 LSB across backends (G10). **Shaders are budgeted by texel rate per device class** (adjusted after critique): a Mali-G52 MC2 at ≈0.85 GHz executes 2 texels/clock/core ≈ 3.4 Gtexel/s peak, so a 9-tap kernel over 1080p (18.7 M fetches) is ≈5.5 ms at peak and ≈7.8 ms peak / 10–15 ms realistic at the G3 geometry (DPR 3, 2.96 MP) — on top of the trilinear base pass and the 3 ms upload box inside a 16.7 ms frame; an Intel iGPU or Apple GPU (≥20 Gtexel/s) does the same pass in <1 ms.

| Pass | When | Kernel | Cost |
|---|---|---|---|
| Cross-level trilinear | every L\* tile with parent resident | bilinear in child and parent, `mix(c, p, f)` | 2 fetches/fragment |
| Transient magnification | ancestor drawn with s > 1.0 (gesture only) | **W+ and N**: Catmull-Rom bicubic via the few-tap bilinear trick (GPU Gems 2 ch. 20); **W− (floor Android) and W60 (Safari/WKWebView incl. the 2020 iPad): plain bilinear** (adjusted after critique: was "≈0.3–1 ms at 1080p on Mali-G52", 5–10× low; and 01/06 disagreed on whether the floor phone was W−) | 4–9 fetches/fragment: <1 ms on W+/N GPUs; 5.5–15 ms on Mali-G52, hence excluded there |
| Sharpening (CAS) | **off by default; never at rest; never at s ≤ 1.0**; a reader-study arm only (gap-1 F9) | FidelityFX CAS, strength ∝ magnification, capped 0.4 | one 3×3 pass, W+/N only |
| 16-bit window/LUT | fluorescence | per-channel `(lo, hi, gamma, colour, inverted)`, additive or max, 8 channels per pass, multi-pass beyond; N visible channels = N fetches per fragment, budgeted like the transient kernels (§13 channel caps) | Viv semantics (MIT) |
| ICC 3D-LUT | raw-pixel sources only (§12) | 33³ RGBA8 texture, one dependent fetch after blending | ≈144 KB |
| Dither | 16-bit → 8-bit output | ordered 4×4 | negligible |

```wgsl
// cross-level sample; f = clamp(-log2(s_child), 0, 1) from the instance buffer
let c = textureSample(tiles_c, samp, in.uv_c, i32(in.layer_c));
let p = textureSample(tiles_p, samp, in.uv_p, in.layer_p);
var rgb = mix(c.rgb, p.rgb, in.f);
if (in.lut_enabled != 0u) { rgb = textureSample(lut3d, lut_samp, rgb * lut_scale + lut_bias).rgb; }
```

UV coordinates are clamped to texel centres (`[0.5, 511.5]/512`) so bilinear never reads outside the tile; tile edges are continuous image data, so the missing cross-tile interpolation is sub-LSB on tissue and is checked by the seam detector on the synthetic slide's Siemens stars that straddle tile boundaries. G3 carries a variant with transients active (ancestor magnification over 50 % of the viewport), not only 60 blended tiles. **Dx mode** freezes the resampler: trilinear cross-level blend, bilinear only (no bicubic, no CAS, no derived tiers), gamma-space filtering, documented kernels — the "fixed resampler" of RA §5, part of the frozen Class C `pathway_hash` (RA §3.2).

## 12. Colour management

- **Brightfield canonical (DICOM WSI, JPEG baseline)**: the scanner ICC → sRGB transform is applied at ingest only when pixels are re-encoded (tier C/D or synthesised levels); passthrough tiles (tiers A/B, >90 % of volume) keep the vendor bytes and the Manifest carries the ICC profile reference. Tiles are served **untagged** so Firefox's qcms and Chromium's Skia do not transform them (the self-certification in G8 depends on this) and the client applies the profile itself: the Edge Translator publishes a 33³ LUT per slide (ICC → sRGB, computed once by `lcms2`/`moxcms` server-side, ≈144 KB, cached forever, versioned in the Manifest) and the shader applies it after blending. Baking into pixels is reserved for re-encoded and lazily synthesised levels, where re-encoding happens anyway, and the level-boundary ΔE between passthrough and synthesised levels is a golden test. **This is now the decision of record** (RA §5 amendment 2, "server-computed, client-applied"; *Requirements* FR-V8 and the colour tests in *Quality, testing and performance QA* §4 follow it; recorded as an ADR because it fixes the Dx pathway): the earlier "server-baked ICC" was impossible for byte-passthrough tiles without breaking the byte identity the brightfield canonical is built on and reintroducing the second pixel copy RA §9 rejects. If the regulatory section ever needs pixels that are colour-correct *in the file*, the only honest alternative is a re-encoded Dx copy, and that is a storage-cost decision, not a renderer one.
- **Filtering space**: `Rgba8Unorm`, i.e. filtering in gamma-encoded space, in both Nav and Dx modes, recorded in the Dx pathway version. gap-2's wgpu probe used `Rgba8UnormSrgb` (hardware sRGB decode, linear-light filtering); gamma-space filtering is specified because (i) hardware sRGB decode is implemented with vendor LUT approximations and threatens the ≤1 LSB cross-backend golden, (ii) at s = 1.0 with pixel-aligned sampling the vendor JPEG pixel is reproduced exactly, which is the property a cleared pixel pathway wants, and (iii) every deployed pathology viewer filters in gamma space, so the validation study compares like with like. Linear-light filtering is kept as a Nav-mode experiment if minification quality on the synthetic Siemens stars shows a measurable gain.
- **Output**: sRGB framebuffer everywhere; Display-P3 (`drawingBufferColorSpace`, Chrome 104 / Firefox 132 / Safari 16.4 **[verified]**) offered in Nav mode only; Dx mode is sRGB because the display is part of the cleared pipeline (display QA and the pairing problem are covered in *Product pillars* and *Regulatory pathway to FDA clearance and the free-distribution model*).
- **Multichannel canonical (OME-Zarr 16-bit)**: no ICC; per-channel transfer functions from `omero` metadata; additive compositing; the ingest-derived 8-bit tier first (§8, §13).
- **Telemetry** records `colour_path ∈ {passthrough+LUT, baked, raw16, derived8}` per frame so the Dx record states exactly which transform produced each pixel.

## 15. Measurement plan and acceptance gates

**Instruments** (note 10 F4 tiers, mapped to this section). Tier 0: Criterion/Divan on `tick`, scheduler, eviction; CodSpeed simulation mode on every PR. Tier 1: deterministic frame tests — CDP `HeadlessExperimental.beginFrame` with one virtual vsync per frame, recorded tile responses replayed by mitmproxy under shaped conditions (RTT 1/25/45 ms and the p95 variants, loss 0/1 %, 5/20/25/100/1,000 Mbps; a real kernel TCP stack via `tc netem` on the lab bridge so slow start is exercised — CDP emulation has none), the renderer's per-frame quality record diffed as a **semantic golden** (`insta` snapshots of draw list, blend weights, upload order, requests, cancels — policy-level fields across platforms, slot ids per platform), screenshots decoded against the synthetic slide's fiducials (level/x/y micro-barcodes, Siemens stars) to prove the record honest. Tier 2: real browsers with `chrome.gpuBenchmarking.pinchBy/smoothDrag` through the real input pipeline and Chromium `LatencyInfo`/`EventLatency` for input-to-swap (pointer and wheel separately). Tier 3: lab devices (W-4G Mali-G52 and Adreno 610 and Xclipse, 2020 A12 iPad, iPhone 12, Firefox Linux, N-\* reference devices; procurement dated in *Repository structure* S1-00 — floor Android and 240 fps camera on the bench in week 0, iPad/iPhone/Xclipse/photodiode rig by Sprint 3, WALT by M1 target / M2 latest) with Macrobenchmark/MetricKit/Perfetto. Tier 4: photodiode rig and 240 fps camera for I2P, WALT for drag latency, and the **reference quad apps** (CSS-transform page; raw Metal; raw Vulkan+SurfaceView) that define REF per device and firmware; the iPad quad app also logs touch timestamps to measure UIKit delivery rate.

**Per-frame quality record** (schema fixed from M0, emitted identically on every platform): `frame_id, t_present, mode (Nav|Dx), build (ruo|learn|clinical|dx), L*, s, dpr, dpr_cap_reason, k, viewport_px, visible_tiles, deficit_max, deficit_area_weighted (incl. blend weight), ntf, blank_px, fade_active, pop_in, upload_bytes, upload_tiles, upload_ms, upload_gpu_ms, tick_ms, draw_ms, inflight_bytes, prefetch_inflight_bytes, bdp, bw_ewma, rtt_p50, l0_occupancy, l0_arrays_cooling, budget_rung, thermal_event, rendering_complete, colour_path, bytes_per_tile_at_Lstar, tile_tier (settled|moving|derived8)`; per gesture: `TTS_warm_settle | TTS_cold, settle_class (chs_hit|cold), BAT, BER, CHS, waste (moving-tier bytes included), bytes_per_gesture, burst_amplitude, burst_duration, lead_observed, inter_burst_gap, hover_prefetch_hit`; per open: `TTFF, TTLS`. The record is what the TSP abstract measures and what the Dx verification evidence cites; `bytes_per_tile_at_Lstar` re-fits the per-level byte model at M1.

**Acceptance gates.** All thresholds live in `gates/*.json` in the repository (the single source from which the gate tables in sections 01/02/05/08/12 are generated); Stage-0 gates are `NFR-G01…G13`, zoom requirements `NFR-P*` with values owned by *Requirements*; the harness emits `quality.jsonl`; CI compares distributions (N ≥ 10 runs, bootstrap CI on p95) against a per-device baseline and fails on shift beyond the noise band or on any hard threshold. A waiver is a reviewed file in the same directory, visible on the public dashboard; a gate is never silently lowered (an agent proposes, a human accepts, per the execution-loop section). Every gate names its **viewport geometry** (W-LAN/N-Desk 3840 × 2160 DPR 1; W-BB 1920 × 1080 DPR 1 with 4K recorded; W-4G/N-And at the DPR-2 cap; W-iPad 2160 × 1620 DPR 2) and its network profile.
