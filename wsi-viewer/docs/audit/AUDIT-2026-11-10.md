# Stoipath audit, 2026-11-10

Scope: repository `RPBatman/Stoipath` (branch `ccr-b12f6228-wup7tf`, PR #2 into `main`), the published site (orphan branch `stage0-deploy` at `c1eab77`, checked from a local copy), and the committee-facing documents. Read-only audit. Six dimensions were audited and each finding was then re-checked by a second reviewer; this report merges their verified findings. Evidence folders named below (`security-privacy/`, `docs-vs-reality/`, `repo-hygiene/`, `licences-attribution/`, `accessibility-consistency/`, `cost-ledger/`, each with a `-verify` twin) sit beside this file. Paths without a prefix are under `/home/user/Stoipath/wsi-viewer/`. "Deploy tree" means the local copy of the published branch.

## Headline for the owner

The software itself held up well: no data leaves the browser, no script-injection path was found, the published pages load cleanly, the measurement numbers in the documents match the committed exports, and the learner pages carry the educational and draft labels. What is not ready for a committee is the wrapping around it. The project is called "open-source" and the Learn pages state "Apache-2.0", but the public repository has no licence file and no record of the campus technology-commercialisation (OTC) approval that the project's own plan requires before the repository is public or the word "open-source" is used. Published design documents describe an AI agent role as "a practising pathologist/educator" without saying no human pathologist was involved. The practice-report page went live although its own specification says not to publish until you answer five questions and a Safari colour check is done, and its automated checks were failing at that moment. The site's front door is a developer measurement page that is hard to use on an iPhone and never mentions Learn or the practice report, and the executive summary and READMEs describe a project several days and two products behind what exists. Almost all of this is wording, records and settings, fixable in a few hours each, but four items need your decision first: the OTC status, the practice-page questions, what the front door should be, and whether AI model names in commit history are acceptable.

## Medium findings, by area

### Security and privacy

**B1. `?manifest=` on the measurement page, the research shell and the comparator loads a slide from any origin and shows it under Stoipath branding** (SP-1). Owner decision. Size S.
- Evidence: `shell.html?manifest=http://127.0.0.1:8902/manifest.json` made 87 GETs to the foreign origin (manifest plus tiles); the slide rendered under the "RUO · For Research Use Only" bar and the foreign licence text appeared in the header chip. `index.html?overlay=1&manifest=<foreign>` made 86 foreign GETs; `comparator/osd.html?manifest=` made 6. `learn.html` and `signout.html` made 0. Code: `stage0/client/src/pyramid.ts:377-378` returns any explicit value unchecked; `src/shell/core/shell.ts:285` and `viewer.ts:434` use it; `stage0/comparator/osd.js:257-262` does the same. The other link parameters are origin-checked (`shell/library/catalogue.ts:208-214`, `learn/host/env.ts:49-55`, `state-url.ts:205`). `TOOLS.md:767` calls `?catalogue=` "the one link parameter that could name another site's slide list", but `?manifest=` also names one (`TOOLS.md:776`). Only `learn.html` and `signout.html` carry a meta CSP.
- Verification: confirmed on a separate server pair (ports 8951 and 8952). A hostile licence string containing a script tag rendered as literal text; no script ran. The behaviour is documented in `TOOLS.md` (LB10), but contradicts the intent stated for the other parameters. The exploit needs the attacker to host CORS-enabled tiles; no user data leaves. The second reviewer notes low is defensible.
- Impact: anyone can send a link on the project's host that shows a slide of their choosing, for example one with a visible patient label, framed as a Stoipath research view. That undercuts "only public de-identified slides" for someone following a link.
- Fix: apply the same-origin rule to `?manifest=` on the shell and comparator, with a persistent notice on refusal and a fall-back to the default. For the measurement page, an allowlist (this origin plus the CAMELYON bucket) or a visible "external slide, not from Stoipath" banner; that page is frozen, so the owner decides. A meta CSP alone is not the fix, because worker fetches are not covered (`SIGNOUT.md:799`).

**B2. The gate-reviewer model is not enforced by the repository: no branch protection or rulesets, and secret scanning, push protection and dependency alerts are off** (SP-5, RH-07). Owner decision. Size S.
- Evidence: `gh api repos/RPBatman/Stoipath/branches/{main,stage0-deploy,ccr-b12f6228-wup7tf}/protection` returns 404 "Branch not protected" for all three; `/rulesets` returns `[]`; `security_and_analysis` shows secret_scanning, secret_scanning_push_protection and dependabot_security_updates "disabled"; all three merge methods allowed; delete_branch_on_merge false. All 14 commits on the published branch were pushed directly by the agent identity, with no pull request. `executive-summary.md:18`, `:165` say humans act "only as reviewers at defined gates". CI also takes its test tiles from the unprotected published branch (`.github/workflows/stage0-ci.yml:107-117`).
